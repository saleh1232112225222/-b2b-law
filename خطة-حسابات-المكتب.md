## قواعد السلامة البرمجية — ملزمة للمطوّر (الذكاء الاصطناعي)

> **تحذير صارم:** هذه القواعد غير قابلة للتجاوز تحت أي ظرف.
> أي مخالفة تعني التوقف الفوري والإبلاغ قبل المتابعة.

### 1. حماية الكود القائم

| مسموح | محظور |
|-------|-------|
| إضافة أسطر وأعمدة جديدة داخل الملفات المحددة في الخطة | حذف أو تعديل أي سطر خارج نطاق المهمة الحالية |
| تعديل الدوال والأنواع المذكورة صراحةً في الخطة | إعادة كتابة ملف كامل موجود (overwrite) |
| قراءة الملف كاملاً قبل أي تعديل | تعديل ملف بدون قراءته أولاً |
| استخدام `multi_replace` للتعديلات الدقيقة غير المتجاورة | تعديل دوال لا علاقة لها بالمهمة الحالية |
| الحفاظ على كل `import` و`export` موجود | حذف أي `import` أو `export` موجود مسبقاً |
| الحفاظ على كل `router.get/post/put/delete` موجود | حذف أي مسار API موجود لم يُذكر في الخطة |

---

### 2. أمان مسارات API

**محظور تماماً:**

```
1. إضافة أي مسار API بدون requirePermission(...)
2. إضافة مسار يعدّل بيانات شركة أخرى (company_id مختلف)
3. استخدام مدخلات المستخدم مباشرةً في استعلامات SQL بدون معاملة ($1, $2...)
4. عدم التحقق من company_id عند قراءة/تعديل أي سجل
5. إرجاع بيانات حساسة (كلمات مرور، tokens) في الرد
6. كشف رسائل خطأ تقنية مفصّلة للعميل (stack trace)
```

**القالب الصحيح الواجب اتباعه في كل مسار:**

```typescript
router.post('/engagements/:id/payments',
  requirePermission('create_finances'),  // واجب دائماً
  async (req: any, res) => {
    const { companyId, userId } = req.auth  // من auth فقط، ليس من body
    const { id } = req.params

    // لا تعدّل أي سجل إلا بعد التحقق من company_id
    const result = await query(
      'SELECT * FROM table WHERE id = $1 AND company_id = $2',
      [id, companyId]
    )
    if (!result.rows.length) {
      return res.status(404).json({ error: 'غير موجود' })  // رسالة مبسطة
    }

    try {
      // المنطق
      res.json({ success: true })
    } catch (err) {
      console.error(err)                                     // للسجل فقط
      res.status(500).json({ error: 'حدث خطأ في المعالجة' }) // بدون تفاصيل
    }
  }
)
```

### 3. سلامة قاعدة البيانات

| المبدأ | السبب |
|--------|-------|
| لا تحذف أعمدة موجودة | قد تخدم أجزاء أخرى من النظام |
| لا تغيّر نوع عمود موجود | سيكسر بيانات قائمة |
| لا تحذف `DEFAULT` من أعمدة لها قيم | ستتحول إلى NULL غير متوقع |
| استخدم `IF NOT EXISTS` دائماً | تجنّب كسر Migration عند إعادة التشغيل |
| لا تحذف Foreign Key موجود | سيكسر التكامل بين الجداول |
| لا ترفع `ON DELETE CASCADE` غير مذكور في الخطة | سيحذف بيانات تلقائياً عند حذف السجل الأب |

## 1. نظرة عامة

### 1.1 الهدف

بناء نظام ذكي لإدارة دخل المكتب — ليس مجرد تسجيل محاسبي، بل نظام يتتبع دورة حياة الدخل بالكامل من أول تواصل مع العميل وحتى إغلاق الحساب.

### 1.2 المشكلة الحالية

| الميزة | الوضع الحالي |
|--------|-------------|
| تسجيل دفعة | زر "تسجيل دفعة جديدة" فارغ بدون handler |
| جدول أقساط | لا يوجد — `paid_amount` حق واحد فقط |
| سجل دفعات | لا يوجد — لا تاريخ، لا من دفع، لا كيف |
| حساب عميل مركّز | لا يوجد — كل قضية منفصلة |
| تنبؤ بالمستحقات | لا يوجد — لا dates، لا reminders |
| إغلاق مالي | لا يوجد — لا حالة "مغلق" |
| تعديل الأتعاب | يوجد تعديل كامل بدون تأريخ للسبب |

### 1.3 دورة حياة الدخل في المكتب

```
استفسار العميل
    │
    ▼
عرض سعر / اتفاقية أتعاب
    │
    ▼
اعتماد الأتعاب ──────────────────┐
    │                             │
    ▼                             │
إصدار فاتورة                     │
    │                             │
    ▼                             │
تحصيل (كامل / جزئي / أقساط)     │
    │                             │
    ▼                             │
متابعة المستحقات والتنبيهات      │
    │                             │
    ▼                             │
تعديل الأتعاب (زيادة/تخفيض) ◄───┘
    │
    ▼
إضافة خدمات جديدة
    │
    ▼
إغلاق الحساب
```

### 1.4 أنواع الدخل المدعومة

| النوع | التصنيف في DB | أمثلة |
|-------|--------------|-------|
| أتعاب قضايا | `legal_service` | مدني، تجاري، عمالي، أحوال شخصية |
| استشارات | `consultation` | حضورية، هاتفية، إلكترونية |
| صياغة عقود | `contract_drafting` | بيع، شراكة، إيجار، عمل |
| مراجعة عقود | `contract_review` | مراجعة وتعديل |
| إنذارات وخطابات | `legal_notice` | إنذار، مطالبة |
| تنفيذ أحكام | `enforcement` | تنفيذ سندات وأحكام |
| اعتراضات واستئناف | `appeal` | لائحة اعتراض، استئناف |
| توثيق | `notarization` | وكالات، إقرارات |
| اشتراكات سنوية | `subscription` | عقود سنوية مع الشركات |
| خدمات أخرى | `other` | أي خدمة قانونية إضافية |

### 2.2 تطبيق السيناريوهات على الموديل

#### السيناريو 1: سداد كامل

```
1. العميل يدفع 30,000 ريال
2. POST /office-accounts/engagements/:id/payments

3. النظام يُنشئ voucher (receipt) تلقائياً
4. يحدث:
   - legal_engagements: paid_amount = 30000, remaining_amount = 0, finance_status = 'paid'

```

```
2. العميل يدفع 10,000 ريال

4. يحدث: paid_amount = 10000, remaining_amount = 20000, finance_status = 'partial'
5. يظهر في الذمم المدينة مع تاريخ استحقاق
6. إذا تم إنشاء جدول أقساط → يظهر القسط القادم

```

```
2. يُنشأ 4 سجلات في payment_schedules
3. يحدث: installment_count = 4, installment_frequency = 'monthly'
4. كل شهر: قسط واحد مستحق

```

#### السيناريو 5: تحويل خدمة إلى قضية

```
1. خدمة استشارة بـ 500 ريال (مدفوعة بالكامل)
2. تم التحويل إلى قضية
3. يتم تحديث engagement_type_id
4. المبلغ المدفوع (500) يُحسب ضمن الأتعاب النهائية
5. remaining_amount = total_compensation - 500
6. finance_status = 'partial' (إذا كانت الأتعاب الجديدة > 500)
```

#### السيناريو 8: زيادة الأتعاب

```
1. أتعاب أصلية = 20,000 ريال
2. PUT /office-accounts/engagements/:id/adjust-fee

   - financial_compensation = 35000
   - remaining_amount = 35000 - paid_amount
   - original_compensation = 20000 (يُحفَّظ للأول مرة فقط)

```

#### السيناريو 9: تخفيض الأتعاب

```
1. أتعاب أصلية = 30,000 ريال
2. PUT /adjust-fee

3. يحدث:
   - financial_compensation = 25000
   - discount_amount = 5000
   - discount_reason = "خصم للعميل المتميز"
```

#### السيناريو 11: دفع زائد

## 3. المرحلة 1: بنية البيانات

### 3.1 جداول جديدة

#### 3.1.1 `payment_schedules` — جدول الدفعات / الأقساط

```sql
CREATE TABLE payment_schedules (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID NOT NULL,
  legal_engagement_id UUID NOT NULL REFERENCES legal_engagements(id) ON DELETE CASCADE,
  installment_number INTEGER NOT NULL,
  title TEXT NOT NULL,
  amount NUMERIC(12,2) NOT NULL,
  due_date DATE NOT NULL,
  paid_amount NUMERIC(12,2) DEFAULT 0,
  paid_date DATE,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending','paid','overdue','cancelled')),
  payment_method TEXT,
  voucher_id UUID REFERENCES vouchers(id),
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_payment_schedules_engagement ON payment_schedules(legal_engagement_id);
CREATE INDEX idx_payment_schedules_status ON payment_schedules(status);
CREATE INDEX idx_payment_schedules_due_date ON payment_schedules(due_date);
```

**الحقول:**

| الحقل | النوع | الوصف |
|-------|-------|-------|
| `id` | UUID | المعرف الفريد |
| `company_id` | UUID | معرف الشركة |
| `legal_engagement_id` | UUID | معرف الخدمة القانونية (مرتبط بـ CASCADE) |
| `installment_number` | INTEGER | رقم القسط (1, 2, 3...) |
| `title` | TEXT | عنوان القسط (مثال: "القسط الأول") |
| `amount` | NUMERIC(12,2) | مبلغ القسط |
| `due_date` | DATE | تاريخ الاستحقاق |
| `paid_amount` | NUMERIC(12,2) | المبلغ المدفوع من هذا القسط |
| `paid_date` | DATE | تاريخ الدفع الفعلي |

#### المسار 1: `POST /engagements/:id/payments` — تسجيل دفعة

**Request Body:**
```json
{
  "amount": 10000,
  "payment_method": "cash",
  "payment_schedule_id": "uuid-optional",
  "notes": "دفعة أولى"
}
```

**خطة التنفيذ:**
1. جلب بيانات الـ `legal_engagements`
2. حساب `newPaidAmount = paid_amount + amount`
3. حساب `newRemaining = (financial_compensation + tax) - newPaidAmount`
4. تحديد `financeStatus`: paid / partial / pending
5. تحديث `legal_engagements` (paid_amount, remaining_amount, finance_status)
6. تحديث `finances` المرتبطة
7. إنشاء `vouchers` (sند قبض) تلقائياً
8. إنشاء سجل في `payment_history`
9. تحديث `payment_schedules` إذا كان الدفع مرتبطاً بقسط
10. تحديث `client_accounts`

**الكود:**

```typescript
router.post('/engagements/:id/payments',
  requirePermission('create_finances'),
  async (req: any, res) => {
    const { companyId, userId } = req.auth
    const { id } = req.params
    const { amount, payment_method, payment_schedule_id, notes } = req.body

    // 1. جلب بيانات الـ engagement
    const engResult = await query(`
      SELECT * FROM legal_engagements
      WHERE id = $1 AND company_id = $2 AND deleted_at IS NULL
    `, [id, companyId])
    if (!engResult.rows.length) {
      return res.status(404).json({ error: 'الخدمة القانونية غير موجودة' })
    }

    const eng = engResult.rows[0]
    const newPaidAmount = Number(eng.paid_amount || 0) + Number(amount)
    const totalDue = Number(eng.financial_compensation || 0) + Number(eng.tax || 0)
    const newRemaining = totalDue - newPaidAmount
    const newStatus = newPaidAmount >= totalDue ? 'paid'
      : newPaidAmount > 0 ? 'partial' : 'pending'

    // 2. تحديث legal_engagements
    await query(`
      UPDATE legal_engagements
      SET paid_amount = $1, remaining_amount = $2, finance_status = $3, updated_at = NOW()
      WHERE id = $4
    `, [newPaidAmount, newRemaining, newStatus, id])

    // 3. تحديث finances المرتبطة
    await query(`
      UPDATE finances
      SET paid_amount = $1, remaining_amount = $2, status = $3, updated_at = NOW()
      WHERE legal_engagement_id = $4 AND company_id = $5
    `, [newPaidAmount, newRemaining, newStatus, id, companyId])

    // 4. إنشاء سند قبض (voucher)
    const voucherCount = await query(
      'SELECT COUNT(*) FROM vouchers WHERE company_id = $1', [companyId]
    )
    const voucherNumber = `VCH-${new Date().getFullYear()}-${(parseInt(voucherCount.rows[0].count) + 1).toString().padStart(4, '0')}`

    const voucherResult = await query(`
      INSERT INTO vouchers (company_id, client_id, case_id, account_id, voucher_number,
        type, amount, date, payment_method, notes, reference_type, reference_id, created_by, updated_by)
      VALUES ($1, $2, $3, NULL, $4, 'receipt', $5, CURRENT_DATE, $6, $7, 'legal_engagement', $8, $9, $9)
      RETURNING id
    `, [
      companyId,           // $1
      eng.client_id,       // $2
      eng.case_id,         // $3
      voucherNumber,       // $4
      amount,              // $5
      payment_method || 'cash',  // $6
      notes || `دفعة للخدمة القانونية ${eng.engagement_number}`, // $7
      id,                  // $8 (reference_id)
      userId               // $9 (created_by & updated_by)
    ])
    const voucherId = voucherResult.rows[0].id

    // 5. تسجيل في payment_history
    await query(`
      INSERT INTO payment_history (company_id, legal_engagement_id, payment_schedule_id,
        amount, payment_method, voucher_id, notes, received_by)
      VALUES ($1, $2, $3, $4, $5, $6, $7, $8)
    `, [companyId, id, payment_schedule_id || null, amount,
      payment_method || 'cash', voucherId, notes || null, userId])

    // 6. تحديث payment_schedule إذا كان الدفع مرتبطاً بقسط
    if (payment_schedule_id) {
      const schedResult = await query(
        'SELECT paid_amount, amount FROM payment_schedules WHERE id = $1', [payment_schedule_id]
      )
      if (schedResult.rows.length) {
        const sched = schedResult.rows[0]
        const newSchedPaid = Number(sched.paid_amount || 0) + Number(amount)
        const schedStatus = newSchedPaid >= Number(sched.amount) ? 'paid' : 'pending'
        await query(`
          UPDATE payment_schedules
          SET paid_amount = $1, paid_date = CURRENT_DATE, status = $2, voucher_id = $3, updated_at = NOW()
          WHERE id = $4
        `, [newSchedPaid, schedStatus, voucherId, payment_schedule_id])
      }
    }

    // 7. تحديث client_accounts
    await upsertClientAccount(companyId, eng.client_id)

    res.json({
      success: true,
      paid_amount: newPaidAmount,
      remaining_amount: newRemaining,
      finance_status: newStatus,
      voucher_id: voucherId,
      voucher_number: voucherNumber
    })
  }
)
```

```typescript
      WHERE id = $3
    `, [installments.length, frequency || 'monthly', id])

    // تحديث finances
    await query(`
      UPDATE finances SET payment_schedules_count = $1, updated_at = NOW()
      WHERE legal_engagement_id = $2 AND company_id = $3
```

```typescript
      WHERE legal_engagement_id = $4 AND company_id = $5
```

```typescript
async function upsertClientAccount(companyId: string, clientId: string) {
  if (!clientId) return

  const result = await query(`
    SELECT
      COALESCE(SUM(e.financial_compensation + e.tax), 0) as total_due,
      COALESCE(SUM(e.paid_amount), 0) as total_paid,
      COALESCE(SUM(e.remaining_amount), 0) as balance
    FROM legal_engagements e
    WHERE e.client_id = $1 AND e.company_id = $2 AND e.deleted_at IS NULL
  `, [clientId, companyId])

  const overdueResult = await query(`
    SELECT COALESCE(SUM(ps.amount - ps.paid_amount), 0) as overdue_amount
    FROM payment_schedules ps
    JOIN legal_engagements e ON ps.legal_engagement_id = e.id
    WHERE e.client_id = $1 AND ps.company_id = $2 AND ps.status = 'overdue'
  `, [clientId, companyId])

    : Number(overdue_amount) > 0 ? 'overdue' : 'active'

      total_due = $3, total_paid = $4, balance = $5, overdue_amount = $6,
      last_payment_date = CURRENT_DATE, status = $7, updated_at = NOW()
```

```vue
        </v-btn>
```

```vue
    </v-card>
```

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'
import { useFinanceStore } from '../../stores/finance'

const props = defineProps<{
  modelValue: boolean
  engagement: any
}>()

const emit = defineEmits<{
  'update:modelValue': [v: boolean]
  saved: []
}>()

const store = useFinanceStore()
const amount = ref(0)
const method = ref('cash')
const notes = ref('')
const saving = ref(false)

const methods = [
  { text: 'نقدي', value: 'cash' },
  { text: 'تحويل بنكي', value: 'bank_transfer' },
  { text: 'شيك', value: 'check' },
  { text: 'بطاقة', value: 'card' }
]

const formatMoney = (v: number) => (v || 0).toLocaleString()

watch(() => props.modelValue, (v) => {
  if (v && props.engagement) {
    amount.value = Number(props.engagement.remaining_amount || 0)
    method.value = 'cash'
    notes.value = ''
  }
})

const handleSave = async () => {
  saving.value = true
  try {
    await store.recordPayment(props.engagement.id, {
      amount: amount.value,
      payment_method: method.value,
      notes: notes.value || undefined
    })
    emit('saved')
    emit('update:modelValue', false)
  } finally {
    saving.value = false
  }
}
</script>
```

- [ ] يمكن تسجيل دفعة كاملة مع إنشاء سند قبض تلقائي
- [ ] يمكن تسجيل دفعة جزئية مع تحديث الرصيد والحالة
- [ ] يمكن إنشاء جدول أقساط وعرضه وتحديثه
- [ ] يمكن تعديل الأتعاب (زيادة/خفض) مع حفظ السبب والتأريخ
- [ ] يمكن عرض الملخص المالي لكل عميل (كل خدماته + إجماليات)
- [ ] يمكن رؤية الأقساط المستحقة والمتأخرة
- [ ] يمكن إغلاق الحساب عند اكتمال السداد (remaining = 0)
- [ ] تقرير حسابات المكتب يُظهر: إجمالي الإيراد، المحصل، المستحق، المتأخر
- [ ] غرامة التأخير تُحتسب وتُضاف بشكل صحيح

### جودة التنفيذ
- [ ] جميع السيناريوهات الـ20 قابلة للتطبيق
- [ ] لا يوجد أخطاء TypeScript
- [ ] لا يوجد أخطاء ESLint
- [ ] البناء ناجح بدون تحذيرات (`npm run build`)
- [ ] الواجهة تعمل على سطح المكتب والجوال
- [ ] المسارات الـ API تُعيد responses صحيحة
- [ ] جدول `client_accounts` يتحدث تلقائياً بعد كل دفعة
- [ ] سند القبض (voucher) يُنشأ تلقائياً مع كل دفعة

### سيناريوهات الاختبار اليدوي
- [ ] إنشاء خدمة جديدة ← تسجيل دفعة كاملة ← التحقق من سند القبض
- [ ] إنشاء جدول أقساط ← دفع قسط محدد ← التحقق من تحديث القسط
- [ ] تخفيض الأتعاب ← التحقق من `discount_amount` + `original_compensation`
- [ ] دفع مبلغ زائد ← التحقق من `remaining_amount < 0` + رصيد دائن
- [ ] فتح تقرير المكتب ← التحقق من أرقام الإجماليات
